# Simple Sender v3.20

This release adds the current readiness/recovery presentation, application-owned validated job snapshots, digest-bound worker source identity, exact placement preflight where it can be proven, and the compact read-only job summary. It also carries forward controller-confirmed stream suspension, exact streamed Tool Change ownership, an exclusive Auto-Level controller lease, fail-closed realtime-write handling, physical-stop recovery for Auto-Level cancellation, and unit-safe dynamic tool-length-offset reconstruction for Resume From.

Connection readiness and execution recovery now show phase-specific operator guidance with expandable technical details. The normal readiness prompt remains non-modal, **Home Later** only dismisses the reminder, and execution recovery explicitly refuses to open while the screen is locked. The Home action uses the protected homing lifecycle and current-session Home-to-Idle evidence before Job Ready.

Read Job now creates an application-owned, file-backed canonical snapshot, computes its SHA-256 digest, and validates the complete bounded command stream before the source can be committed as runnable. Run and Resume From do not perform another copy, hash, or whole-job validation pass. The worker source identity carries the snapshot digest, byte size, and validated executable-line count; a missing or changed snapshot blocks execution before streaming begins.

Run and Resume From now keep span checks separate from machine-envelope placement. Exact absolute linear targets are projected with the existing automatically captured `$130/$131/$132` settings and fresh trusted MPos/WCO/WCS/G92/TLO/modal caches. A verified violation blocks execution. An unverifiable result names the reason and requires confirmation; this adds no controller query and changes no GRBL streaming, acknowledgment, pacing, or EOF behavior.

The read-only job summary above the console shows the loaded filename and current readiness or blocking guidance. During running or paused jobs it shows run time excluding pauses and estimated remaining time when available. It refreshes from current state at most once per second through the existing UI loop; it does not enable controls, verify physical setup, or replace the existing status and recovery dialogs.

Safety Door and external Hold reports close ordinary stream and tool-change macro/probe transmission immediately. Cycle Start remains unavailable until GRBL reports `Door:0`; closing the door does not itself resume the job, and the sender still waits for controller confirmation after the operator requests Resume. If a `TC:` directive remains pending, that confirmation returns to the independent Tool Change pause and does not release the next job line.

Every streamed Tool Change command and completion is bound to one opaque connection/serial/stream/recovery/source/directive identity. Delayed, reconstructed, duplicate, or prior-session workflow work cannot command or complete a replacement directive. If the UI receives a current replacement while a stale prior workflow thread is still alive, it signals the stale workflow and explicitly fails the replacement with Stop/restart guidance instead of silently leaving it pending.

Auto-Level now exclusively owns worker command admission from atomic acquisition through fresh PRB/Idle validation, callback publication, modal restoration, and a two-phase map installation. Successful restoration creates one exact single-use installation ticket. Ordinary machine-driving commands remain blocked while the UI stages the result; only final worker revalidation can atomically publish the map and enable Apply/Save. Installed maps carry exact controller/session/source/coordinate/trust provenance and are invalidated by reset, alarm, recovery, disconnect/replacement session, source replacement, or relevant WCS/G92/TLO changes. Historical loaded maps remain inactive. A retired workflow or failed restoration/finalization cannot install a stale map. Current-session jog-cancel write failure enters Recovery Required even if cached status appears Idle. Resume From rejects same-block tool-length ambiguity such as multiple `G43.1`, `G49`, or associated Z words instead of applying textual order.

The existing Phase 0 recovery ownership, connection-generation isolation, source transactions, completion ownership, and Kasa safety barriers remain in place.

Current Windows / Python `3.12.1` validation as of `2026-09-11`: `run_tests.bat` passed all seven stages with `2647 passed, 1 skipped` (the environment-gated physical Kasa test), 74% total line coverage, 89.2% aggregate critical-path coverage, and no Ruff, compileall, manifest, or configured-mypy failures across 141 source files.

Cross-platform CI, hardware-in-the-loop behavior, and Raspberry Pi image provenance/build validation were not run. Hardware-in-the-loop behavior is not implied by the software test suite. Use a physical emergency stop or power isolation, begin without spindle power or a cutter, and verify controller state after every reset or recovery.
